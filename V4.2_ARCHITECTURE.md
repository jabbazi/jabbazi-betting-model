# JABBAZI GURU V4.2 Reliability Layer\n\nThis branch adds the first deployable reliability layer on top of the V4.1 operating system.\n\n## Implemented\n\n- **Model promotion engine** — `SHADOW_ONLY -> VALIDATING -> LIMITED_LIVE -> PRODUCTION_APPROVED`.\n- **Market-relative validation** — promotion can require the model to outperform a market-only Brier baseline.\n- **Incremental-edge accounting** — model probability, no-vig market probability, break-even probability, raw model/market gap, and expected ROI stay separate.\n- **Data-integrity kill switches** — stale prices, unsupported markets, event mismatch, market-pair mismatch, unhealthy features, and malformed probabilities fail before model approval.\n- **Complementary-outcome validation** — catches normalization/pairing defects like the historical Toronto/Baltimore run-line issue documented in V4.1.\n- **CLV lifecycle** — observed, recommended, entry, and closing price fields plus probability-point CLV.\n- **Portfolio concentration** — real-dollar exposure by event and thesis tag; no invented effective units.\n- **Model-lane decision gate** — only `PRODUCTION_APPROVED` can produce `BET_NOW` from the model lane.\n\n## Compatibility with V4.1\n\n`SHADOW_ONLY` remains research-only. A model-lane WATCH does **not** globally block a candidate that independently passes the broader V4.1 research and execution gates.\n\nPromotion must be tracked **per sport + market bucket**, not just per sport. Example: MLB moneyline may validate while MLB totals remain SHADOW_ONLY.\n\n## Recommended cloud persistence\n\nFor each frozen pre-event prediction persist:\n\n1. model/version and sport/market bucket\n2. canonical event + selection + period + threshold + settlement identity\n3. frozen model probability and uncertainty fields actually returned\n4. paired no-vig market probability and quote timestamp\n5. scanner recommendation timestamp and play-to price\n6. user entry only when confirmed\n7. comparable closing price\n8. settlement/result\n9. data-health flags\n10. Brier/log-loss/calibration/CLV bucket outputs\n\nThese records feed promotion decisions. ROI is retained but should not be the sole promotion criterion.\n\n## Conservative defaults\n\nThe numeric promotion thresholds in `PromotionPolicy` are starting defaults, **not claims that the current NFL/MLB models have passed them**. They should be tuned only from prospective frozen predictions and documented validation.
